# Эффективность и корректность расчётов

- title: Себестоимость игнорирует материалы операций
- description: `calc_cost` берёт материальную стоимость из `calc_bom`, а не из норм операций, поэтому изменения `route_operation_material` на расчёт не влияют. Проверено на PostgreSQL: для 1000 `ПК-01.001` стоимость материалов равна нулю при наличии в маршруте норм фарша, оболочки и клипс (`schema.sql:1927–1929`); блок материалов на вкладке маршрута также обращается к BOM (`core/static/js/route.js:478–487`).
- severity: Error
- type: Bug
- location: `schema.sql:2086–2088`

- title: Полуфабрикат из нормы операции не попадает в анализ и расчёт труда без дублирования в BOM
- description: `find_route_deep` определяет дочерние изделия только через `find_bom`, а API позволяет указать полуфабрикат в операции независимо от BOM (`core/service.py:2080–2103`). В PostgreSQL для штатного `ПК-01.001` анализ выдал только три операции самой колбасы: три операции фарша `ПФ-01.001`, указанного в норме расхода операции, не попали и в `calc_labor`.
- severity: Error
- type: Bug
- location: `schema.sql:2010–2019`

- title: Пустая новая версия маршрута убирает трудоёмкость изделия из расчёта
- description: SQL берёт наибольший номер версии без учёта выбранной в интерфейсе и делает внутреннее соединение с её операциями; при создании новой версии UI сперва сохраняет пустую шапку (`core/static/js/route.js:281–288`) и не передаёт выбор в запросах расчёта (`core/static/js/route.js:460–461,489,500`). В PostgreSQL добавление пустой версии №2 для `КЛ-01.001` оставило в `find_route_deep` три строки фарша и убрало три операции батона, хотя версия №1 осталась.
- severity: Warning
- type: Bug
- location: `schema.sql:2021–2025,2049–2052`

- title: Округление до копеек перед масштабированием искажает стоимость труда партии
- description: `find_route_deep` округляет стоимость каждого вхождения на одно конечное изделие (`schema.sql:2046–2048`), затем `calc_labor` умножает округлённую сумму на размер партии. На штатном заказе из 1000 `КЛ-01.001` получилось 5 570,00 ₽ за работу оператора куттера вместо 5 573,33 ₽ при округлении после умножения; погрешность растёт с размером партии и числом вхождений.
- severity: Warning
- type: Bug
- location: `schema.sql:2070–2074`

- title: Сводные расчёты разворачивают все пути до одинаковых компонентов
- description: Рекурсивный `UNION ALL` вызывает `bom_effective` заново для каждого вхождения, наращивает два массива пути и только после разворачивания сортирует дерево (`schema.sql:1027–1031`); `calc_bom` и `calc_labor` группируют уже развёрнутые строки. В слоистом DAG из 2 изделий на уровень, где каждое включает оба изделия следующего уровня, количество обрабатываемых строк растёт как 2^глубина, хотя количество записей норм растёт линейно; для детального вывода это обусловлено контрактом, для сводных расчётов это лишняя работа.
- severity: Warning
- type: Performance
- location: `schema.sql:993–1010`

- title: Один пересчёт интерфейса запускает пять обходов состава
- description: Четыре HTTP-запроса интерфейса отдельно считают детализацию, BOM, труд и себестоимость; первые три выполняют по одному обходу, а себестоимость повторяет оба сводных (`schema.sql:2086–2088`). Смена количества заново скачивает и рендерит даже детализацию, которой количество не передаётся (`core/static/js/route.js:461,510–511`), что особенно дорого для больших составов.
- severity: Warning
- type: Performance
- location: `core/static/js/route.js:460–511`

- title: Поздний ответ старого пересчёта может подменить новый результат
- description: Вызовы `loadRouteCalc` не отменяют предыдущие запросы и не сверяют актуальные изделие/количество перед обновлением общих HTML-блоков. На больших составах при быстрой смене количества или изделия медленный ответ предыдущего запроса может заменить одну из таблиц уже после ответа текущего запроса, так что разные блоки будут показывать разные партии.
- severity: Warning
- type: Concurrency
- location: `core/static/js/route.js:450–511`

Прямые проверки выполнены в чистой временной PostgreSQL 18.3 с загруженным `schema.sql`; оценки роста путей, числа обходов и гонки получены по коду без бенчмарка.
