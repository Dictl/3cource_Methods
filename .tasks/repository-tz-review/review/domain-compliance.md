# Соответствие предметной области и заданию № 6

Проверка статическая. Номера страниц относятся к `Задание №6.pdf`; номера абзацев DOCX (где указаны) — к последовательности элементов `w:p` в `word/document.xml`, включая таблицы.

## Findings

- **title:** Свод материалов берётся из спецификации вместо операций маршрута
  **description:** `calc_bom` обходит только `find_bom`, а экран маршрутов запрашивает `/api/bom/<id>/calc/`; изменение нормы материала операции не изменяет свод. Хранимые `MR_Q` и `SUM_MR` со стр. 21 задания и заявленные в DOCX не реализованы; соответствующих API для расчёта нормы операции и свода маршрута тоже нет (`core/urls_api.py:127–132`).
  **severity:** Error
  **type:** Design
  **location:** `core/static/js/route.js:478–487` (источник данных `schema.sql:1036–1077`; нормы операций `schema.sql:1726–1735`).

- **title:** Стоимость материалов считается не по данным техпроцесса
  **description:** `calc_cost` берёт труд из `calc_labor`, но материалы из `calc_bom`, а не из норм операций. Даже при назначенных материалах операции стоимость материалов будет нулевой для изделия без BOM, а при несовпадающих нормах BOM и маршрута — будет отражать BOM.
  **severity:** Error
  **type:** Bug
  **location:** `schema.sql:2078–2089` (BOM-агрегация `schema.sql:1057–1076`).

- **title:** Отчёт приписывает анализу технологичности поиск отсутствующих маршрутов
  **description:** В DOCX §1.3 и §4.1 (рис. 11), таблицах 4 и 8 заявлены `find_no_route` и `/technology/<id>/no-route/`; в БД и API их нет. Это потенциальная дополнительная проверка полноты данных: пройти BOM, выписать только изготавливаемые компоненты без маршрута (например, фарш, если бы ему не задали техпроцесс), не считать покупное сырьё и упаковку ошибкой; обязательный `FIND_TM` решает обратную по форме задачу — выводит существующие строки операций через внутренние `JOIN`, не диагностируя пропуски.
  **severity:** Warning
  **type:** Documentation
  **location:** `core/urls_api.py:127–132`; `schema.sql:2011–2057`; DOCX абзацы 40, 168–172, 279–281, 370–372. Критерий изготавливаемости в проекте: `schema.sql:534–547`, `schema.sql:1943–1955`. При наличии только «шапки» без операций проверка существования маршрута и проверка его заполненности дали бы разные результаты; не смешивать.

- **title:** Пример вызова FIND_TM и выбор версии в DOCX не работают
  **description:** В §4.1 показан вызов `find_route_deep(id, 1000)`, в таблицах 4 и 8 заявлены параметры партии и выбора версии. SQL и сервис принимают только `product_id`, всегда берут маршрут максимального номера и рассчитывают количества для единицы изделия; это расхождение с отчётом, а не само по себе пробел в `FIND_TM(pIdEl)` из PDF.
  **severity:** Warning
  **type:** Documentation
  **location:** `schema.sql:1989–2025`; `core/service.py:2130–2133`; `core/api_views.py:2045–2052`; DOCX абзацы 146–150, 276–278, 368–369.

- **title:** Отчёт описывает подготовительное время, которого нет в реализации
  **description:** В БД есть только норма на единицу `time_norm`; часы операции линейны по количеству, и `calc_labor` масштабируется на партию, поэтому ни `setup_time`, ни отдельного учёта Tпз, ни формулы из §2 фактически нет. В PDF Tпз есть в моделях (стр. 8–9, 11–12), но отдельно не сформулирован в ключевых требованиях (стр. 3), поэтому нельзя говорить, что PDF его вообще не упоминает; отчёт должен различать проектную модель и фактический расчёт.
  **severity:** Warning
  **type:** Documentation
  **location:** `schema.sql:1702–1714`, `schema.sql:2041–2048`, `schema.sql:2062–2075`; DOCX §1.2–1.3, §2–4, таблицы 2–5, заключение.

- **title:** Граф состояний и входов операций заявлен, но не хранится
  **description:** В §2–3 DOCX заявлены `result_state` и `source_operation_id`, а PDF в варианте 2 моделирует состояния и связывает потребителя с выходом конкретной операции («Изделие-Операция»). Таблицы хранят только порядок и ссылку материала на `product_id`, поэтому нельзя определить, какая предыдущая операция дала вход, а анализ следует по BOM, а не по сети входов операций.
  **severity:** Warning
  **type:** Design
  **location:** `schema.sql:1704–1735`, `schema.sql:2011–2057`; DOCX абзацы 74, 103, 199, 225, 237, 251, 255.

- **title:** Типовые техпроцессы из проектного расширения не поддержаны
  **description:** PDF на стр. 14–16 показывает общий шаблон, параметры конкретного изделия и расчёт на их основе. Реализованные версии маршрута принадлежат конкретному изделию и не имеют ссылки на общий шаблон; имеющиеся параметры каталога с маршрутным расчётом не связаны. Учитывать как покрытие проектного расширения, если оно входит в оцениваемый объём.
  **severity:** Info
  **type:** Design
  **location:** `schema.sql:1692–1735`, `schema.sql:1989–2089`; `core/service.py:1794–1817`.
